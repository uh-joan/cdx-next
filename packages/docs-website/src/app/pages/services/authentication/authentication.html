Seamless Login

Authentication component supports Seamless Login by implementing the OAuth 2.0 standard by generating a session (JWT) through the exchange of an auth_code for a JWT from the 1P Auth server.

In summary, the flow is as follows:

  1. Login page (MicroUI) will continue to be hosted under https://access.[env].clarivate.com.

  2. After successful login by the user, the MicroUI will redirect the user to the application with the auth_code via a path param, e.g. https://apps.[env].clarivate.com/[appId]/broker/:[auth_code]

  3. The application can then utilize the @cdx/ngx-authentication component to exchange the auth_code for a token.

  4. Upon successful exchange of the auth_code for a JWT, the app can then redirect to its own home / landing page.


NOTE: The application domain and the path is configurable at the MicroUI.

Configuration

Install @cdx/ngx-authentication package Import and configure AuthenticationModule in your root module's imports list. Configure the required appName and eventually the other options.

Environment is not mandatory, it can be left empty and you'll be redirected to the production site. You may optionally set these additional configurations when calling AuthenticationModule.forRoot()

  • tokenLabel (defaults to 'token'): Sets the localStorage key prefix e.g. ls.token,
  • brokerRoute (defaults to 'broker/:authCode'): Sets the url of the broker component. It will need to contain a ':authCode' path to get the value of the authcode

Usage

Utilize the AuthenticationService to manage user logout and get a redirection url for the user.

Using header (hlx-header) with authentication

Authentication can be easily integrated using the cdx-header-global-user-profile that belong to HeaderGlobalUserProfileModule and it is intended to be used inside the cdx-header, but it can be used independently of it.
