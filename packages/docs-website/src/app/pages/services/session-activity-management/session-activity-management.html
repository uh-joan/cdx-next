Session Activity

After a certain amount of configurable time of inactivity a popup will be opened, to continue the session the user will have to click on continue session to continue the navigation, if not at the end of the countdown the user will be logged out. Session Activity popup

Rehydrate

Once the continue session button is clicked or once some amount of configurable ping interval amount of time is passed (while some action are performed during that amount of time) the rehydrate API 'api/session/user/rehydrate' is called to keep the backend aware of the fact that the session is active.

Configuration

  1. Install @cdx/ngx-session-activity

    2. Once @cdx/ngx-session-activity is installed, also @ng-idle/core and @ng-idle/keepalive should be installed automatically as peer dependency


  2. Import and configure SessionActivityModule in your root module's imports list.
  3. 💡 You may optionally set these additional configurations when calling SessionActivityModule.forRoot( )

    • expireDurationMinutes: (defaults to 22): Sets the interval in minutes after which the user will be logged out for inactivity.

    • expireWarningMinutes: (defaults to 2): Sets countdown in minutes that will be displayed in the popup. It is important for this value to be smaller than expireDurationMinutes, because the popup opens after expireDurationMinutes - expireWarningMinutes of inactivity.

    • pingIntervalMinutes: (defaults to 30): Sets the interval in which the rehydrate ('api/session/user/rehydrate') function will be called.

    • shouldNotRehydrate: Sets to true if the rehydrate function should not be called.

Usage

Utilize the SessionActivityService to manage session activity and logout for the user.

Where sessionActivityEvent is a signal emitted from session-activity.service once logout button is clicked as LOGOUT_TYPE.LOGOUT_SELECTED or once countdown expire with no action as LOGOUT_TYPE.SESSION_EXPIRED.

The parameters that we are passing to the module can be also passed to the function sessionActivityService.initialize(), in case we also have injected those parameters to the module they'll be overridden.

Using header (hlx-header) with authentication and session activity

Session activity management is already integrated in the header, it will need only the import of the SessionActivityModule with optional configurations as shown before and the cdx-header-global-user-profile (that will require also AuthenticationModule. ) component that contains the authentication inside it the withSessionManagement directive will be responsible of adding the session management.
