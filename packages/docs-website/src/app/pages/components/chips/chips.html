The Helix chip component is built using selected styles from the Angular Material chip framework. For implementation details, see the Code tab.

Options

Color and styles

Chips combine color themes and styles to represent information or actions in a clear, compact way.

Standard chips:

  • Neutral – This can be used as the default. Unselected state.
  • Outlined – This can be used as the default. Unselected state.
  • Primary – Use when a chip needs clear emphasis. Selected state.
  • Basic – Use for simple or optional actions.
  • Accent – Use sparingly for actions or content that need extra emphasis.

Semantic chips reinforce meaning:

  • Negative – Use for errors or destructive context.
  • Positive – Use for success or confirmation.
  • Warn – Use for cautionary states.
  • Info – Use for neutral or informational context.

Density

Chips are available in three size options, controlled by the density setting.

  • Density 0 is the default and most commonly used.
  • Use alternative densities to create a clear visual hierarchy—sparingly and with purpose.

Icons

Icons help clarify meaning, but should never be purely decorative.

  • Use a leading icon to reinforce the label’s intent.
  • Use a trailing icon to suggest interactivity, such as removing the chip.

For guidance on choosing and applying icons, see .

Chips vs. buttons

Buttons are consistent, familiar, and best suited for progressing users through key steps or significant actions. Chips are more dynamic, appearing in groups to support the current context with quick, lightweight interactions.

  • Use chips to enhance a person’s journey, show states and provide contextual options.
  • Use buttons to move them forward in the product and for primary actions.

Type

  • Does the chip represent an action? → assist chip
  • Can the user filter results? → filter chip
  • Is its content coming from the user? → input chip
  • Is its content generated by the product? → suggestion chip

Usage

Use chips to present contextual, supplemental options or filter results. Don't use chips for primary actions. Use buttons for moving users forward in a process. Use chips to show statuses or states (e.g., Completed). Don't use chips to display static data, such as dates.
