An entity detail page shows one record. off-x-ui's Snapshot is the source: an entity header, a summary card of the key facts, then an accordion of sections that load lazily and are disabled when empty — so the user sees at a glance what the record has and only pays for the sections they open.

When to use it

The detail view of one record — a drug, trial or target — reached from a or search. A collection is a list; a short record is just a card.

Shape

  1. Entity header — name (the page's h1), type, key metadata, actions (the heading area).
  2. Summary card — the handful of facts the user came for, no clicks needed.
  3. Sections — a mat-accordion; each loads on first open and shows its own . Empty sections are disabled.

Do

  • Lead with the header and a summary card; keep the depth in the accordion.
  • Load each section on first open; show its four states inside the panel.
  • Disable (or mark) sections with no data.
  • Keep one h1 (the entity name).

Don't

  • Expand and load every section up front.
  • Leave empty panels openable only to show "no data".
  • Skip the summary and start with accordions.
