When a whole route can't be shown, give the user a real page — not a blank screen or a bare code. Each error page is an hlx-empty-state (tone="error") centred in the content area, with a plain explanation and one clear way forward — the same component as the in-region error, at page scale, served by the router inside the .

The three

  • 404 — the page doesn't exist → go to home (or search).
  • 403 — you don't have access → request access / go back.
  • 500 — something went wrong our end → retry, then contact support.

Do

  • Build from hlx-empty-state; centre it in the content area.
  • Give one primary action that fits the error.
  • Explain in plain words; no codes-only pages, no stack traces.
  • Keep the shell (header/nav) around the error.

Don't

  • Show a bare code or a stack trace.
  • Leave the user with no way forward.
  • Use a full error page when only one region failed (that's a Page states error).

An error page

Route them inside the shell: a wildcard route for 404, a guard redirect for 403, and a global ErrorHandler for 500 (offer Retry).
