AG Grid is the right tool for large, sortable, filterable, column-managed data. This pattern is the one Helix setup: modules and licence registered once, a Theming-API theme built from the --hlx-* tokens, shared column defaults, and persisted column state.

When to use it

Large or column-managed datasets. For a short, read-mostly list use a mat-table instead (see ); the toolbar, chips and around the grid are the same either way. See also the component.

Do

  • Register modules and the licence once, via provideHelixAgGrid().
  • Use the Theming-API helixGridTheme and HELIX_DEFAULT_COL_DEF.
  • Persist and reset column state per grid.
  • Build the toolbar, chips and states from the composing patterns.

Don't

  • Scatter ModuleRegistry.registerModules or the licence key.
  • Use the legacy CSS theme, or bespoke .ag-* overrides, for a new grid.
  • Grow one grid component with feature-flag booleans — use config or variants.
  • Let a column-managed grid forget the user's layout.

One setup, shared

Register AG Grid once at bootstrap:

Bind the Theming-API theme and the shared default column def. The theme is built from the --hlx-* custom properties, so the grid follows the app theme.

provideHelixAgGrid, helixGridTheme and HELIX_DEFAULT_COL_DEF ship from @cdx/theme-ag-grid; the Theming-API theme supersedes the package's legacy CSS theme for new grids.
