A dialog interrupts the user for one decision or one short task. Anything longer belongs on a page; a passive message belongs in a snackbar or hlx-notification.

When to use it

  • Confirming a decision, especially a destructive one.
  • A short, focused task such as a small form.
  • Showing detail beside the current page without navigating away (a side panel).

Sizes

Open every dialog through a named preset — sm, md, lg, side, fullscreen — never with a raw width. One set of widths keeps dialogs consistent.

Do

  • Open through a size preset.
  • Build the body from mat-dialog-title / -content / -actions.
  • Keep autoFocus on and order actions so the safe one is focused.
  • Use hlx-btn-negative for a destructive confirm, and give any close button aria-label="Close".

Don't

  • Pass a raw width such as '80vw'.
  • Turn autoFocus off to avoid focusing a destructive button — order the actions instead.
  • Build the body from mat-card inside the dialog.
  • Rely on window.confirm.

A size helper

Open every dialog through a named preset. Until the theme ships these panel classes, define the helper once in your app and the widths in your global styles (see the pattern guide for the SCSS).

Body structure

Corners (border-radius-default) and the overlay shadow (elevation-lg) come from the theme — you do not set them. align="end" puts the actions on the right, Cancel before the destructive Delete, so focus lands on Cancel.
