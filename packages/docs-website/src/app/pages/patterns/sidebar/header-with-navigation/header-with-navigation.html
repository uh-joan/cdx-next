When to use

Use this layout when your product has complex information architecture and multiple features or destinations.

  • Prefer horizontal navigation (header) for primary structure when possible.
  • Add a sidebar when:
    • You need secondary navigation because important items don’t fit in the header.
    • Users need persistent access to certain tools or destinations if they don’t fit in the header.

Use cases

1. Secondary navigation

High-priority destinations that users access frequently. If these don’t fit in the header, place them in the sidebar:

  • Saved searches
  • Bookmarks
  • Alerts or Notifications

2. Quick access switching within modules

  • Example: navigating between product sections or modules.
  • If this toggling can’t be supported cleanly in the header, add a sidebar to preserve user context.

Design considerations

  • Use horizontal navigation in the header for primary and high-priority destinations whenever possible to maximize space and clarity.

Dos and don'ts

Don't repeat options from the horizontal menu; if you need to do it for a legitimate reason, use the same icon in both places. Do not duplicate a section on the horizontal menu and sidebar. For example: don't use the sidebar for one-time actions (like “Log out” or “Profile Settings” — those belong in the header).
