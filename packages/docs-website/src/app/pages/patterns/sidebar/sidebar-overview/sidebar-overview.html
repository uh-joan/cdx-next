Definition

  • Common alternative names: Sidebar, Sidebar menu, Side navigation / Sidenav, Navigation rail, Vertical navigation, Left nav, Drawer, Navigation panel. Use “Sidebar” or “Side navigation / Sidenav” as the standard label in documentation and design tools.
  • Position: Usually fixed to the left side (commonly) or right side of the screen.
  • Purpose: Help users efficiently navigate through major areas or tools of a product, especially when there are multiple unrelated destinations or features.

Frequent menu items

The sidebar frequently hosts those links: home, settings, Cortellis or Clarivate family links, Alerts/notifications, Saved searches, Search history, Updates/Latest news.

Use cases

Use horizontal navigation (on the component) as the primary navigation for your product. The sidebar is restricted to the use cases below only:

  • : Products that require both primary and secondary navigation.
  • (products with navigation that includes subcategories).
  • (Sidenav): For products where it's standard to use side nav as a main navigation instead of horizontal menu (for instance, AI chats or app-like products, e.g. ChatGPT).

Behavior and rules

  • Scrolling: Destinations should remain visible and fixed when scrolling vertically.
  • Use icons only for first-level navigation items. Sub-level (nested) items should be text-only to maintain a clear and consistent hierarchy.

Best practices

  • Should contain between 3-7 navigation items.
  • The side bar should be on the left and can be controlled by a navigation menu icon for responsive or dense UIs.
  • Don’t overload the side nav; keep it scannable.
  • Use visual structure when the side bar is complex, for instance:
    • Top part: links related to the product itself
    • Bottom part: generic Clarivate links (e.g. Cortellis products, Clarivate products)
    • Use section headers or horizontal dividers for better scanning if the nav is long or to separate groups of navigation
  • Do not repeat options from the horizontal menus; if you need to do it for a legitimate reason, use the same icon in both places.
  • Pair icons with text labels and avoid icon-only navs when possible. If using collapsed side navs, show only icons but provide tooltips on hover.
  • When collapsed, the label text should be one clear word that describes the destination and helps users understand the icon. In the case you cannot use only one word, avoid wrapping long labels when possible and do not truncate labels. If necessary, create a line break between words. Don’t shrink the type scale to fit longer text labels.

Accessibility

  • All navigation items must be accessible and operable via keyboard (Tab, Arrow keys, Enter, etc.) and screen reader accessibility for an inclusive experience.
  • Group related items together (use <ul> and <li> properly).
  • Support responsive behavior: collapse or hide the sidebar on smaller screens.
