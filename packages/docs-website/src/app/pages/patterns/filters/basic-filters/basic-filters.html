Applies to one to five or six filters per use case. This limit can vary depending on the layout, but it's important to ensure filters always stay on a single line across all screen resolutions to maintain a clean and consistent design.

When to use it

Choosing the right use case will improve usability and user efficiency.

  • Data visualization
  • Table
  • Entity page with small sets of data
  • The most used filters on an entity or results page

Components used

  • Search
  • Dropdown lists

Frequently used functionalities

  • Clear all / Select all: To clear the selected options.
  • Reset: When there’s a default configuration users might want to restore.
  • Search inside the list: When the list of items is quite long.
  • Cancel / Apply buttons: When filters cannot update results in real-time.

Best practices

  • Use for common & high-frequency actions: Quick filters should address the most used or high-frequency filtering actions to minimize user effort.
  • Keep labels short & clear: Use concise, descriptive labels that are immediately understandable.
  • Show active states clearly: Provide a clear visual indicator (e.g., highlight, checkmark, pill state) when a quick filter is active, to reinforce user feedback.
  • Limit the number of quick filters: Display only the most relevant filters to avoid overwhelming users. Prioritize based on user needs and usage data.
  • Maintain a single line layout: Ensure quick filters stay on a single line across screen sizes to keep the interface clean and scannable. In case more filters need to be added, they can be inside a general filter button. Use case: "The most used filters on an entity or results page."
